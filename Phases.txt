Yes. Based on the repo audit we just did, I would **replace the old roadmap entirely** rather than keep patching it. This version starts from what Sepulchria actually has now and does not pretend Inventory, Market, Events, Rules, etc. still need to be built. 


# PHASE 8 — COMPLETE ENGINEERING & SECURITY AUDIT

**This is the large cleanup we've deliberately postponed.**

At this point, **feature development stops temporarily**.

### 8.1 — Database integrity audit

Inspect every important database relationship:

* Foreign keys.
* Cascades.
* Restricts.
* `SET NULL`.
* Unique constraints.
* Check constraints.
* Indexes.
* Orphan prevention.

Especially character/account deletion.

### 8.2 — Transaction audit

Identify every operation touching multiple tables.

Examples:

* Market purchase.
* Market sale.
* Player trade.
* Item transfer.
* Item use.
* Character deletion.
* Mission reward.
* Combat resolution.
* Spell casting.
* Staff economic actions.

Move critical operations into atomic database transactions/RPCs where appropriate.

No more:

> query A succeeds → query B fails → portal is left half-updated.

### 8.3 — Concurrency audit

Test deliberately:

* Double-click purchase.
* Simultaneous trades.
* Two browser tabs.
* Duplicate submissions.
* Simultaneous item use.
* Concurrent rewards.
* Simultaneous combat actions.

Prevent duplication and race conditions.

### 8.4 — Complete RLS/security audit

Review **every table**.

Test separately as:

* Anonymous visitor.
* Normal player.
* Moderator.
* Master.
* Admin.
* Owner.

Attempt direct database operations rather than trusting UI visibility.

### 8.5 — Server-action security audit

Every mutation must validate server-side:

* Authentication.
* Character ownership.
* Permissions.
* Input.
* Current state.
* Target eligibility.

### 8.6 — Input and content security

Audit:

* Rich text.
* HTML.
* URLs.
* Images.
* User-generated content.
* Uploads.
* Forum.
* Chat.
* Profiles.
* Codex/Rules administration.

### 8.7 — Rate limiting / abuse prevention

Protect:

* Login.
* Registration.
* Chat.
* PMs.
* Instant Chat.
* Forum.
* Reports.
* Support.
* Trades.
* Market.
* Combat.
* Spell actions.

### 8.8 — Deletion lifecycle

Make deletion explicit and deterministic.

Audit what happens when deleting:

* Account.
* Character.
* Item.
* Room.
* Area.
* Event.
* Mission.
* NPC.
* Spell.
* Rule/Codex content.

Historical ledgers/logs must remain valid without making legitimate deletion impossible.

### 8.9 — Migration reconstruction

Ensure the complete database can be recreated from version-controlled migrations.

### 8.10 — Dependency audit

* Remove unnecessary packages.
* Pin/upgrade dependencies appropriately.
* Resolve vulnerabilities.
* Verify Next.js/Supabase compatibility.

### 8.11 — CI

GitHub should automatically run at minimum:

* Type checking.
* Linting.
* Build.
* Automated tests.

Broken code should not quietly reach production.

### 8.12 — Performance

Audit:

* N+1 queries.
* Oversized queries.
* Unnecessary client components.
* Image loading.
* Pagination.
* Revalidation.
* Presence polling/realtime.
* Chat performance.
* Large inventories/messages/forums.

**Phase 8 complete when:** we trust the architecture rather than merely seeing that the UI works.
